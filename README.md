# pi-rex

Run `pi` from here when the work is about **Rex** (Superlogical's terminal emulator
and multiplexer): sessions, tabs and panes, config, debugging, Rex questions.

Not a Pi package. It installs nothing and publishes nothing — the value is three
config files.

```sh
git clone git@github.com:S1M0N38/pi-rex.git ~/Code/github.com/S1M0N38/pi-rex
cd ~/Code/github.com/S1M0N38/pi-rex
pi
```

Run `pi` from this directory. Pi reads `.pi/` and `.agents/skills/` from where it
starts, so a session opened elsewhere gets neither the skill nor the MCP server.
Starting it inside Rex is better: `REX_SESSION` and `REX_BLOCK` are set, so Pi acts on
the pane it runs in.

| Path | What it does |
| --- | --- |
| `.agents/skills/rex/SKILL.md` | Rex's agent skill, generated by Rex. Tells the agent to print the guide from the installed `rex`, so upgrading Rex upgrades the knowledge. |
| `.pi/mcp.json` | `superlogical` MCP: Rex docs, changelog, Rex Beta Discord threads. Project-scoped, codemode exposure. |
| `AGENTS.md` | Which skill and server to use for what, and the ground rules. |

Requirements: Rex running here (`rex whoami --json`), Pi, and membership of the Rex
Beta Discord for the MCP — sign in once with `pi mcp login superlogical`, check with
`pi mcp list`.

After upgrading Rex: `rex skill setup --project --agent pi`, then commit the diff.
Never hand-edit `.agents/skills/rex`.
