# rex

Two things: my Rex config, and a Pi workspace for working on **Rex** (Superlogical's terminal emulator and multiplexer) — sessions, tabs, panes, config, debugging.

## The config

`~/.config/rex` is a symlink to this repo, so `init.lua` at the root is the live config Rex reads as `$XDG_CONFIG_HOME/rex/init.lua`.

```sh
git clone git@github.com:S1M0N38/rex.git ~/Code/github.com/S1M0N38/rex
ln -sfn ~/Code/github.com/S1M0N38/rex ~/.config/rex
```

Rex reads nothing else in the directory, so `README.md`, `AGENTS.md`, `.pi/` and `.agents/` sit next to the config harmlessly.

## The workspace

Run `pi` from this directory. Pi reads `.pi/` and `.agents/skills/` from where it starts, so a session opened elsewhere gets neither the skill nor the MCP server. Inside Rex is better: `REX_SESSION` and `REX_BLOCK` are set, so Pi acts on the pane it runs in.

| Path | What it does |
| --- | --- |
| `init.lua` | Rex config: bindings, actions, modes. |
| `.agents/skills/rex/SKILL.md` | Rex's agent skill, generated by Rex. Prints the guide from the installed `rex`, so upgrading Rex upgrades the knowledge. |
| `.pi/mcp.json` | `superlogical` MCP: Rex docs, changelog, Rex Beta Discord threads. Project-scoped, codemode exposure. |
| `AGENTS.md` | Which skill and server for what, plus ground rules. |

Not a Pi package; it installs and publishes nothing. Requirements: Rex running here, Pi, and Rex Beta Discord membership for the MCP (`pi mcp login superlogical`, then `pi mcp list`).

After upgrading Rex: `rex skill setup --project --agent pi`, then commit the diff. Never hand-edit `.agents/skills/rex`.
