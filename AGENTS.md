# pi-rex

Where Pi runs when the work is about **Rex** (Superlogical's terminal emulator and multiplexer): driving sessions, tabs and panes, changing Rex config, debugging, answering Rex questions. There is no code in this repo.

## Where you are

You are usually running inside a Rex block. `REX_SESSION`, `REX_BLOCK` and `REX_SERVER` are set; act on them unless the user names another target. If they are unset, start with `rex whoami --json` then `rex ls --json`.

Fleet details — hosts, server modes, session-naming conventions — are deliberately missing for now. Ask rather than invent.

## The rex skill

`.agents/skills/rex` (generated by Rex) teaches the CLI. Load it with `/skill:rex` before inventing commands. If it is not loaded, `rex skill show` prints the same guide.

## Rex docs, changelog and Discord

The `superlogical` MCP server holds Rex documentation, the changelog, and past and current Rex Beta Discord threads. It uses codemode exposure: nothing is declared, so reach it from a `codemode` script.

Tools: `search_docs`, `read_doc`, `list_docs`, `search_changelog`, `read_changelog`, `list_changelog`, `search_feedback`, `get_feedback`, `list_feedback`, `get_attachment`, `list_activity`.

- `describeNamespace('mcp__superlogical')` — server description, instructions, tool names
- `describeTool('mcp__superlogical__<tool>')` — that tool's arguments
- `searchTools('<question>', { namespace: 'mcp__superlogical' })` — ranked tools, when you do not know which one
- `await tools.mcp__superlogical__<tool>({ ... })` — call one

Use it for *why* and *what changed*: design intent, changelog entries, whether a reported bug is known. For *what this machine can do right now*, prefer `rex help`, `rex <command> --help`, and the state commands — the MCP may describe a release newer than the installed server (`rex whoami --json` prints the version).

## Ground rules

- The Rex server holds every terminal on this machine. Never restart or kill it, and never exit sessions or blocks the user did not ask about. Close what you opened.
- Inspect before acting: `rex session inspect --json`, `rex block ls --json`. Prefer full IDs in follow-up commands; labels and short IDs can be ambiguous and exit 3.
- Nothing installs without a human yes. Read-only checks are always fine.

## Maintenance

Do not hand-edit `.agents/skills/rex`. After upgrading Rex, run
`rex skill setup --project --agent pi` here and commit the diff;
`rex skill status --project` reports `current`, `outdated` or `missing`.
