# rex

Where Pi runs for work on **Rex** (Superlogical's terminal emulator and multiplexer): driving sessions, tabs and panes, changing Rex config, debugging, answering Rex questions. No application code here: an agent workspace plus my Rex config.

## Where you are

You are usually inside a Rex block: `REX_SESSION`, `REX_BLOCK` and `REX_SERVER` are set; act on them unless the user names another target. If unset, start with `rex whoami --json`, then `rex ls --json`.

Fleet details — hosts, server modes, session-naming conventions — are deliberately missing. Ask rather than invent.

## The config

`~/.config/rex` is a symlink here, so `init.lua` at the root is live config.

- `rex config check` loads and reports bindings, removals, modes, actions; `rex config reload` applies them.
- A reload applies the file as written: anything it stops declaring disappears from the running server. Never reload a half-written file.
- Rex reads no other file here. Only add config files the installed Rex documents.
- Never delete, move or repoint the symlink.

## The rex skill

`.agents/skills/rex` (generated by Rex) teaches the CLI. Load it with `/skill:rex` before inventing commands; `rex skill show` prints the same guide.

## Docs, changelog and Discord

The `superlogical` MCP server has Rex docs, the changelog and Rex Beta Discord threads. Codemode exposure: nothing is declared, so reach it from a `codemode` script. Tools: `search_docs`, `read_doc`, `list_docs`, `search_changelog`, `read_changelog`, `list_changelog`, `search_feedback`, `get_feedback`, `list_feedback`, `get_attachment`, `list_activity`.

- `describeTool('mcp__superlogical__<tool>')` — arguments; `describeNamespace('mcp__superlogical')` — server info
- `searchTools('<question>', { namespace: 'mcp__superlogical' })` — when unsure which tool

Use it for *why* and *what changed*; for *what this machine can do now*, prefer `rex help`, `rex <command> --help` and the state commands — the MCP may describe a newer release.

## Ground rules

- The Rex server holds every terminal on this machine. Never restart or kill it; never exit sessions or blocks the user did not ask about. Close what you opened.
- Inspect before acting: `rex session inspect --json`, `rex block ls --json`. Prefer full IDs; labels and short IDs are ambiguous and exit 3.
- Nothing installs without a human yes. Read-only checks are always fine.

## Maintenance

Never hand-edit `.agents/skills/rex`. After upgrading Rex, run `rex skill setup --project --agent pi` and commit the diff; `rex skill status --project` reports `current`, `outdated` or `missing`.
